# Reference run: v0.4 live run in claude.ai

A summary of a full live run of v0.4 in claude.ai, in normal chats inside a Project. It covered setup (extending an existing map), two analyses taken through grill, plan, run, review and retro, and one design ask through `/wayfinder-data`. The domain is the invented online shop and subscription app. Data is invented. It is a reference for what a good run catches and what v0.5 fixed, not a graded case: the runner skips this folder because it has no rubric.

A new run should catch at least what is listed under "Caught" and should not repeat what is listed under "Missed in v0.4".

## Caught

| What | Where in the flow |
|---|---|
| The map was found with nothing attached, from the Project files | Start of a flow step |
| A conflict between two answers was named plainly and handled one question at a time | Grill (stuck rule) |
| The decisions log held every question and answer word for word | Grill, Decisions section |
| The hypothesis tree counted the looks (how many cuts would be scanned) before the run, so the multiple-comparison cost was visible in advance | Plan |
| `readout.docx` was built from `readout.md` with the chart embedded | Run |
| The review recomputed the headline numbers in SQL from the raw table, by a route the run did not use | Review |
| The minimum detectable effect was worked out from the baseline, the power and the daily visitors, with the inputs shown | Design ask, plan |
| Christmas seasonality was flagged in the comparison window | Grill |
| A 7-day window that ran past the readout date was flagged | Plan |
| A blocker was named early: the visit marker holds a visitor id while the outcome table holds an account id, so a per-visitor rate could not be joined | Plan, run |

## Missed in v0.4 (fixed in v0.5)

| Seen | v0.5 fix | Item |
|---|---|---|
| A new ask silently resumed yesterday's analysis and skipped the grill. The resumed file also kept "no DATA-MAP.md, so inline" after a map existed, and an old hint in the Meta claim line | The grill asks "Continue `<folder>`, or start a new analysis?" and never resumes silently. A resumed file has stale lines refreshed as "was" and "now" pairs | 5 and 6 |
| A question card asked "which hypothesis paths?" before the tree was shown, and its options were bare ids. One option recommended "sign-ups per visitor" while the map said the visit marker was unknown | Cards show the tree, table or draft first, each option says what it means ("H1.1: holds in each month"), and an option that needs missing data says so | 13 and 15 |
| Two robustness children ("holds in each month", "holds on the raw count") were marked `refuted` when they held, because they were judged against the parent's direction. The review did not catch it | Each node is judged against its own conditions. A robustness child whose result held is `supported`. The review checks every status and fixes wrong ones with a "was" and "now" pair | 16 and 17 |

## Also fixed in v0.5 (seen in the same run)

| Seen | v0.5 fix | Item |
|---|---|---|
| A bare file name landed in a `claude/` folder, and a generic spec name was overwritten by the next spec | One layout under `data-work/`, full paths, specs in their own analysis folder | 1 and 19 |
| One reply said the file was saved and also said to replace the old one | Three save forms only, never a claimed save that did not happen | 2 |
| An older top-level copy (`analysis (6).md`) sat beside the new one, unnamed | Stale copies are named | 3 |
| `readout.md` linked charts under `outputs/` in a chat app | Links use the chart's real path | 4 |
| The map listed three files in one bullet, and grain and keys stayed empty after two analyses | Setup and retro tidy the map to the template as one approved change | 9 |
| Key queries were saved as descriptions only | Key queries are saved as SQL | 8 |
| Hand-back was asked at every grill | It is asked once per Project and recorded in the map | 10 |
| "Recommended if you have one" as a default in the wayfinder and in setup | Real defaults everywhere | 14 |
| The wayfinder ended with no go-ahead question | It ends with the fixed go-ahead question | 18 |

## How to use it

Run the same three jobs in a Project: extend a map, run two analyses end to end (the second on an ask close to the first), and design one test. Compare with the tables above. Record the result in `results/<date>-<agent>.md`.
