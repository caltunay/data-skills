# Reference run: v0.5 live run in claude.ai

A summary of a full live run of v0.5 in claude.ai, in normal chats inside a Project. It covered setup, one analysis through grill, plan, run, review (first in the same chat, then in a new chat) and retro, then `/improve-code`, `/storytell` and a design ask through `/wayfinder-data`. The domain is the invented online shop and subscription app. Data is invented. It is a reference for what a good run catches and what v0.6 fixed, not a graded case: the runner skips this folder because it has no rubric.

A new run should catch at least what is listed under "Caught" and should not repeat what is listed under "Missed in v0.5".

## Caught

| What | Where in the flow |
|---|---|
| Continue or new analysis was asked, not assumed | Grill |
| Answers were echoed back word for word | Grill |
| Gaps in the map were used in the grilling | Grill |
| Robustness statuses were right (judged against each node's own conditions) | Run, review |
| A weekly-block interval check was run | Run |
| Independent recomputes by other routes (SQLite, the standard library, awk, a jackknife) | Review |
| A false "only if" claim was fixed in the second review | Review |
| Sizing assumptions were stated | Design ask |
| An SVG chart saved and rendered in Project files | Run |
| The retro asked for approval per item | Retro |
| Sizing maths was correct | Design ask |
| A broken comparison series was rejected on the data | Design ask |
| An overlap with another spec was found | Design ask |
| The agent disagreed honestly with the user's choice | Design ask |

## Missed in v0.5 (fixed in v0.6)

| Seen | v0.6 fix | Item |
|---|---|---|
| `analysis.md` grew to about 600 lines, one step would not update it, and two reviews missed that the review pack read and wrote temp paths | Every script is its own file in `scripts/`, takes the data folder as an argument, writes into the analysis folder. `analysis.md` lists them. The review runs them from the data folder | 1 and 20 |
| The user was told twice to "move" or "add" a file to a Project folder | Never ask. Say "Download `<file>`" | 4 |
| The most useful line (what it would take to change the answer) sat in the appendix of an exec outline | Lead with the insight a decision needs | 9 |
| Setup saved "where work lives: gap" after the user had answered | Answered items are recorded | 14 |
| The goal link recommended a broad growth goal over the exact target the ask was about | Recommend the goal whose metric matches the ask's metric | 17 |
| A repeat run was called a trusted number in the retro | A number is trusted only after an outside check | 22 |
| `/improve-code` asked twice before running anything | Run old and new itself when it can | 24 |
| `/improve-code` suggested hard-coding a quarter into a reusable query, twice | Keep reusable code reusable | 26 |
| `/improve-code` said a cost "rose each month" where the analysis said no trend can be claimed | Stay in scope, claim ceiling in every skill | 29 |
| The design ask sized a 17-week test before learning the real limit was 4 weeks, and never asked what the saving was worth | Business limits first, size for them, derive the margin from the trade-off | 31 |
| No non-experiment design was offered until the user pushed | Offer other designs in the first round of options | 33 |

## How to use it

Run the same jobs in a Project: setup, one analysis end to end with the review in a new chat, then `/improve-code` on a reusable query and a design ask with a short time limit. Compare with the tables above. Record the result in `results/<date>-<agent>.md`.
